Data handling

Privacy policy

How Drive Inbox accesses, processes, and stores data for a personal document workflow.

Effective date: November 4, 2026

What the app accesses

The importer uses Google's read-only Drive scope, https://www.googleapis.com/auth/drive.readonly. It reads file identifiers, names, file types, timestamps, parent-folder identifiers, links, and change records, and downloads or exports the contents of files selected for import. This permission is broader than access to a single folder.

Why data is used

File metadata is used to identify newly visible files and track import progress. File contents are used to export or convert documents into Markdown and save them in the owner's second-brain inbox. The importer does not modify source files or their sharing permissions in Google Drive.

Where data is stored

  • OAuth access and refresh credentials are stored on the operator's server so scheduled imports can authenticate. The importer sets its credential file permissions to owner-only when saving refreshed credentials.
  • Downloaded content is processed in memory and, when conversion requires it, temporary files on the server. Temporary conversion files are ordinarily removed when processing finishes.
  • Markdown copies are retained in the owner's second-brain inbox. The checkpoint retains known Drive file identifiers and progress information.
  • Run output may include imported file identifiers, filenames, destination paths, file sizes, and error messages.

Sharing and external services

The importer communicates with Google to obtain authorized Drive data and refresh credentials. Document conversion runs locally with MarkItDown plugins disabled; the importer does not send file contents to an external AI service for conversion.

The destination second-brain directory is separately configured to synchronize through Obsidian Sync. Imported Markdown may therefore be transmitted to that service and synchronized devices. Synchronization, backups, and any subsequent use of imported notes are separate from the import script. The operator controls the devices, access, and settings for those systems.

Drive Inbox uses Google data for the personal document-import workflow described here. It does not sell Google data, use it for advertising, or use it to train generalized AI models.

Retention and deletion

The importer does not automatically expire imported Markdown or delete local copies when their Drive originals are deleted. Copies remain until the owner deletes them. Import checkpoints and logs remain until separately removed or rotated. Copies retained by synchronization services, other devices, or backups may require separate deletion under those systems' settings.

Stopping access

The owner can revoke the app's access through Google Account connections and disable the scheduled importer. Revoking access prevents future authorized reads; it does not delete documents already imported. Local copies, credentials, logs, and checkpoint files can be removed separately by the owner. Removing a checkpoint changes future import tracking and should not be treated as a routine authentication repair.

Security

Credentials and imported files belong on the operator's private server, not on this public website or in its repository. The operator is responsible for server access controls, backups, synchronization settings, and credential protection. No system can guarantee absolute security.

This website

This static site has no login, upload form, analytics script, tracking pixel, or application-set cookies. This website is hosted on GitHub Pages. GitHub may process request information, such as IP addresses and server logs, as described in the GitHub General Privacy Statement. Private Drive documents and OAuth credentials are not served by this website.

Changes

Changes to the importer, hosting, synchronization, or data-handling practices will be reflected on this page. The effective date above identifies the current version.
